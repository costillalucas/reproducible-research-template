The worst error: on real data, the program did nothing

The program corrects the image a little in each round. Those corrections were ~8,000 times smaller than they should have been: it returned almost the original photo.

Hundreds of automated tests passed, because they used images of 16 to 32 pixels.

An agent investigating something else found it. Everything done before on real data had to be discarded.

Fixing the step was necessary but not enough: with the December data the result was noise. Credible reconstructions came with the September captures.

6 / 14

What the step is: the program improves the image gradually; it compares the photos it predicts with the measured ones and corrects it a little in each round. Analogy: walking down a mountain in steps of a tenth of a millimetre; after 100 steps you are still where you started. The program delivered the starting photo as if it were the reconstruction. Lesson: passing every test does not guarantee the code works in the real case. Where the 8,000 comes from: the program divided the correction by the number of pixels in the photo (160,000 at 400×400), which is correct, but it used a fixed step of 20 tuned on tests of 16 to 32 pixels, where 20 is reasonable. With real photos, 20/160,000 is 1/8,000 of the normal step. It was not intuitive because it depends on the image size.
